# Release flow

## Sources of truth

- `Cargo.toml` package version is the release version.
- Git tag must match it as `vX.Y.Z`.
- `CHANGELOG.md` holds user-facing release notes.
- `dist-workspace.toml` defines GitHub Release artifacts, shell installer, Homebrew formula, and target platforms.
- `.github/workflows/release.yml` is generated by `dist`.

## Targets published

- crates.io: `cargo install clew`
- GitHub Releases:
  - macOS Apple Silicon tarball
  - macOS Intel tarball
  - Linux x86_64 tarball
  - checksums
  - shell installer
- Homebrew tap: `npatten/homebrew-tap`

Native Windows artifacts are deferred. Use WSL2 for release artifacts.

## Prerequisites

- crates.io access for `clew`
- GitHub access to `npatten/Clew`
- `HOMEBREW_TAP_TOKEN` configured in the Clew repo with write access to `npatten/homebrew-tap`
- local tools: `cargo`, `dist`, `gh`, `git`

## Release checklist

1. Update `CHANGELOG.md` with `## [X.Y.Z] - YYYY-MM-DD` notes.
2. Bump `Cargo.toml` version to `X.Y.Z`.
3. Run `cargo check` so `Cargo.lock` records the new package version.
4. Check packaging:

   ```bash
   dist generate --check --allow-dirty
   dist plan --tag vX.Y.Z --allow-dirty --no-local-paths
   cargo publish --dry-run --allow-dirty
   ```

5. Run the quality gate:

   ```bash
   scripts/promote-clew
   ```

6. Commit the release-ready state.
7. Publish crates.io:

   ```bash
   cargo publish
   ```

8. Push `main`, then create and push the tag:

   ```bash
   git push origin main
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

9. Watch the release workflow:

   ```bash
   gh run list --repo npatten/Clew --workflow release.yml --limit 3
   gh run watch <run-id> --repo npatten/Clew --exit-status
   ```

10. Verify outputs:

    ```bash
    cargo search clew --limit 1
    gh release view vX.Y.Z --repo npatten/Clew
    gh api repos/npatten/homebrew-tap/contents/Formula/clew.rb --jq .content | base64 --decode
    git status --short
    ```

## Changelog practice

Keep release notes in `CHANGELOG.md`. `cargo-dist` uses those notes for the GitHub Release body, then appends install and artifact details.

Do not duplicate prose in the Homebrew formula. crates.io has package metadata and README content, not per-version release notes.

## Maintenance

Regenerate the workflow after changing `dist-workspace.toml` or upgrading `dist`:

```bash
dist generate --allow-dirty
```

Check without writing:

```bash
dist generate --check --allow-dirty
```
